AOBB Code Quality Report

Executive Summary

The Anno 1800 Offline Blueprint Builder (AOBB) codebase successfully implements a robust feature set, but suffers from significant architectural compression. The most critical issue is the Canvas.tsx module, which has absorbed responsibilities across view rendering, domain logic, and state management. The type safety is exceptionally strong, and pure math logic is well-isolated. However, to support parallel development, the tight coupling in the Canvas and UI stores must be unwound.

Methodology

The codebase was reviewed through static analysis of the src/ directory, examining file sizes, dependency imports, and store designs. The evaluation mapped feature flows from the UI component layer down to the Zustand store and pure domain functions. Test coverage was validated by inspecting __tests__/.

Findings by Dimension

Architecture & Module Boundaries Critical

Verdict: Canvas.tsx violates the Single Responsibility Principle significantly. It handles interaction logic (panning, painting), global shortcuts, and rendering simultaneously.

Evidence: src/components/Canvas.tsx:166-215 handles global window keyboard events directly inside the Canvas component. Lines 491-576 manually construct the visual hierarchy of every placed building instead of delegating to a sub-component.

State Management Moderate

Verdict: Global state is mixed with transient UI state, and complex interaction states are hidden in useRef variables.

Evidence: src/state/blueprintStore.ts:9-12 defines selectedIds and activeBuildingId alongside placements. Canvas.tsx:73-88 uses multiple disconnected refs (isDrawingBox, isSpaceDown, isPanning, isManualPanning) which can lead to invalid interaction states. src/components/Palette.tsx:47-63 directly interacts with localStorage inside the component.

Composability & Reusability Moderate

Verdict: UI elements are monolithic. The Konva stage renders everything directly rather than composing smaller reusable layer or node components.

Evidence: src/components/Canvas.tsx:463-488 inline rendering of Influence radius overlay circles. It lacks a <BuildingNode /> or <InfluenceOverlay /> abstraction.

Type Safety & Error Handling Minor

Verdict: Type safety is excellent. No any escapes were found in the application source. Errors in async flows show toasts rather than silently failing.

Evidence: Strong typings in src/lib/productionMath.ts and consistent interface usage in the store. App.tsx:86 correctly captures import errors and pipes them to the toast UI.

Testability & Tests Critical Risk

Verdict: High test coverage for math and data integrity, but zero test coverage for the complex Canvas component, representing a high regression risk for the refactor.

Evidence: src/__tests__/ contains comprehensive tests for productionMath.test.ts and paneLayout.test.ts, but no snapshot or behavior tests for Canvas.tsx or the interaction state logic.

Risk Register

  • Refactoring Canvas without Characterization Tests: Splitting Canvas without a safety net risks breaking panning, zooming, box-selection, or ghost preview logic. A snapshot or manual test script is required.
  • Coordinate Math Regressions: The dragBoundFunc and pan math relies on exact pixel-to-tile ratios. Altering where this logic lives might introduce offset bugs.
